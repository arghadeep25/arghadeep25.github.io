Graph SLAM

A robot walks, gets a little lost with every step, then fixes its whole map in one go. Watch how.

Walking with your eyes closed

The robot counts its steps. Every count is a tiny bit wrong, and the mistakes add up.

Nodes: a pin for every step

Each time the robot moves, it drops a pin. A pin is a guess: where am I, and which way am I facing?

One node of the graph. It holds the robot's guess for step i.

Bigger i: later in the trip.

Smaller i: earlier in the trip.

x: how far along

Distance from the start, sideways on the map.

Bigger x: further to the right.

Smaller x: further to the left.

y: how far up

Distance from the start, up the map.

Bigger y: further up.

Smaller y: further down.

θ: which way it faces

The heading, as an angle.

Bigger θ: turned more to the left.

Smaller θ: turned more to the right.

Edges: a string between two pins

The odometer says what happened between two steps. Tie a string between the pins to hold that fact. If the pins drift away from what the sensor said, the string stretches and pulls them back.

eij: the error

How far the string is stretched. Zero means the pins agree with the sensor.

Bigger: the pins disagree with the sensor more.

Smaller: the string is more relaxed.

zij: what the sensor said

The measured move from pin i to pin j: how far, and how much it turned.

Bigger: the sensor says the robot moved further.

Smaller: the sensor says it barely moved.

h: what the pins say

The move from i to j that you get from where the two pins sit right now.

Bigger: the pins are further apart.

Smaller: the pins are closer together.

xi: the first pin

Where the move started. Move this pin and h changes.

Shifted: the whole string moves with it.

Held still: only pin j can ease the stretch.

xj: the second pin

Where the move ended. The optimiser slides this pin until e shrinks.

Further from the sensor's answer: e grows.

Closer to the sensor's answer: e shrinks.

How sure is each string?

Two strings can disagree. The pin goes nearer the string we trust more. That trust is called information, and it is the second part of every edge.

Ω: a table of three trusts

One trust for each thing a pin holds: x, y and the heading.

Bigger numbers: a sharper, more trusted sensor.

Smaller σ: a precise sensor, so Ω is stiff.

Bigger σ: loose in y.

Smaller σ: stiff in y.

Bigger σ: loose in heading.

Smaller σ: stiff in heading.

Loop closure: "I have been here!"

Look at the strings before the robot returns: all relaxed, and yet the map is wrong. Then the robot recognises the start. One new string joins the last pin to the first, and that string is very stretched. Every pin on the way gets pulled a little, and the lap snaps shut.

One price for the whole map

Every string charges a price for being stretched. Add the prices up and you get one number for the whole map. The best map is the one with the lowest total.

F(x): the total price of a map

x is every pin at once. F says how unhappy all the strings are with it.

Bigger: a worse map. Strings are stretched.

Smaller: a better map. Strings are relaxed.

Σ: add them all up

Go through every string, from pin i to pin j, and add its price.

More strings: more facts to respect, and a bigger total.

Fewer strings: less to respect, so the map is easier to fool.

x*: the best map

The star means the best one. This is the answer we are after.

Higher price at x*: the sensors disagree with each other.

Price near zero at x*: every string is happy.

argmin: the choice that makes it smallest

Try every possible map. Keep the one with the lowest price.

Bigger search: more pins, more to try.

Smaller search: fewer pins, faster.

F(x): the price we are minimising
